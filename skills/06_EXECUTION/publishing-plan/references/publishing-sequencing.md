# Publishing Sequencing

This reference sequences **content launches around dependencies**. It is an execution concern: the question is not which topic is “best,” but what must exist or be verified before another asset can responsibly go live. [Evidence Tier: Tier 3 — Industry observation]

## Sequence dependencies
Identify prerequisite pages, internal-link destinations, technical fixes, expert approvals, legal/compliance review, data collection, image creation, and conversion paths. Publish only when the page can fulfill the user task and the surrounding site can support the next action. [Evidence Tier: Tier 3 — Industry observation]

Use dependency types: **hard dependency** (page cannot function without it), **quality dependency** (missing input would weaken the asset), and **follow-up dependency** (can ship but needs a scheduled post-launch action). This lets the roadmap distinguish true blockers from desirable improvements. [Evidence Tier: Tier 3 — Industry observation]

## Concrete scenario
A comparison page depends on current vendor pricing, an approved product matrix, and a destination page for consultation requests. The publishing plan waits for pricing verification but can prepare the page, schema eligibility check, and internal-link map in parallel. [Evidence Tier: Tier 3 — Industry observation]

## Failure modes
Publishing before evidence approval, creating links to pages that do not yet exist, sequencing by calendar convenience rather than dependency, and treating a content calendar as proof of readiness. [Evidence Tier: Tier 3 — Industry observation]

## Evidence boundary
Sequencing is an operational framework, not a ranking rule. Recommendations follow the centralized governance contract. [Evidence Tier: Tier 1 — Officially documented]

## Release readiness
A publishing sequence should name the exact evidence that must be approved, the destination pages that must exist for internal navigation, the technical checks that must be complete, and the owner who can block release. These are release dependencies, not generic SEO tasks. [Evidence Tier: Tier 3 — Industry observation]

For parallel work, distinguish artifacts that can be prepared from artifacts that must be final. A writer can draft around a known product matrix while pricing verification is pending, but the final publication should not imply that unverified pricing is current. [Evidence Tier: Tier 3 — Industry observation]
